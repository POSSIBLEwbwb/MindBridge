# 产品迭代路线

项目实战的重点不是一次性完成所有功能，而是按产品问题逐步迭代。

## v0：基础可运行

目标：先让系统能跑通。

能力：

- Spring Boot 服务启动。
- 接入大模型。
- 支持用户提问。
- 能返回普通回答和流式回答。

产品问题：只能聊天，不能保证答案依据企业资料。

## v1：文档接入

目标：让企业资料进入系统。

能力：

- 上传 PDF、Word、Excel。
- 原始文件存储到 MinIO。
- 文档元数据写入 MySQL。
- 文档状态开始流转。

解决的问题：企业资料不再散落在本地文件里，而是变成可管理的知识资产。

## v2：文档解析与分段

目标：让文档变成可检索的知识片段。

能力：

- PDF/Word 通过 MinerU 转 Markdown。
- 图片、表格、公式被保留或转成可描述内容。
- Markdown 按标题切分。
- 普通文本按长度和 overlap 切分。
- Excel 走表格结构处理。

解决的问题：整篇文档不能直接向量化，必须切成语义完整、大小合适的片段。

## v3：向量化与检索

目标：让用户问题能召回相关知识。

能力：

- 片段生成 embedding。
- 写入 Elasticsearch 向量索引。
- 支持向量检索和全文检索。
- MySQL 保存片段状态和元数据。

解决的问题：用户不用知道文档在哪里，也能通过自然语言找到相关内容。

## v4：Query 理解和数据源路由

目标：让系统知道问题应该查哪里。

能力：

- LLM 意图识别。
- 结构化 JSON 输出。
- Query 改写。
- 数据源路由：知识库、MySQL、图数据库。
- Text2SQL 查询结构化数据。

解决的问题：不是所有问题都该走向量库，订单、保险、车辆绑定等问题要查数据库。

## v5：混合检索和重排序

目标：提升进入大模型的上下文质量。

能力：

- 向量检索 + BM25 关键词检索。
- RRF 融合多路召回。
- BGE Reranker 本地重排。
- minScore 过滤低相关片段。
- 引用信息补全。

解决的问题：召回多不等于召回准，真正要优化的是 Top-K 上下文质量。

## v6：异步处理和稳定性

目标：让文档处理链路更接近生产。

能力：

- 文档转换完成后发事件。
- 异步切分和向量化。
- XXL-JOB 扫描补偿失败任务。
- 分布式锁避免重复处理。
- 文档状态保证幂等。

解决的问题：文档解析和向量化耗时长，不能全部堵在一次同步请求里。

## v7：效果评测

目标：从凭感觉调参变成看指标迭代。

能力：

- 构建测试问题集。
- RAGAS 评测。
- bad case 归因。
- 对比优化前后指标。

解决的问题：回答不好时，可以定位是检索问题、生成问题，还是评测标准答案问题。

## v8：生成质量和拒答

目标：减少幻觉和错误回答。

能力：

- 优化系统提示词。
- 更换更适合 RAG 的模型。
- ground truth 校准。
- 分层拒答。

解决的问题：知识库没有答案时，系统应该明确说明资料不足，而不是硬编。

## 总结

这条迭代链可以概括为：

```text
能问答 -> 能接文档 -> 能检索 -> 能路由 -> 能重排 -> 能异步稳定处理 -> 能评测 -> 能拒答
```

这比“做一个 RAG Demo”更接近真实产品研发过程。
