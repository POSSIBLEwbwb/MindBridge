# 产品定位

## 一句话

这是一个面向汽车服务场景的多源 RAG 智能客服系统，用来把产品手册、售后政策、车辆信息、订单数据和用户问题连接起来，让客服回答有依据、可追溯、可持续优化。

## 解决的问题

汽车服务场景里，用户的问题经常不是单纯聊天，而是带有明确业务目标：

- 查政策：这车保修期多久？
- 查资料：胎压报警灯亮了怎么办？
- 查业务数据：我的保险还有几天到期？
- 查关系：某个故障会影响哪些功能？
- 投诉售后：维修太慢、服务不满意怎么办？

如果直接把问题丢给大模型，会有三个问题：

- 知识可能过期，回答不一定来自企业资料。
- 业务数据查不到，比如订单、车辆、保险。
- 回答没有引用来源，客服和用户都不容易信任。

所以系统引入 RAG、结构化查询、检索路由和评测闭环，让回答尽量基于证据生成。

## 用户价值

| 角色 | 价值 |
| --- | --- |
| 用户 | 更快拿到准确回答，不用反复描述问题 |
| 客服 | 减少翻文档和查系统的时间 |
| 运营 | 能通过 bad case 看到知识库和回答质量问题 |
| 技术团队 | 有完整链路可以持续评测、定位和优化 |

## 产品边界

系统不是替代所有人工客服，而是优先处理可检索、可解释、可标准化的问题。

对高风险、资料不足或召回质量低的问题，系统应该保守回答或拒答，而不是强行生成。
