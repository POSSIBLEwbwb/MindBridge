# 解决问题重写导致召回不准的问题

## 问题

系统会先对用户问题做 Query 重写，用来简化表达、纠错、补全上下文。但之前实现里，把“用户 ID”和“当前时间”也拼进了改写后的 Query。

这些信息对 Text2SQL 有用，但对向量检索和全文检索是噪声。

## 根因

同一条 Query 承担了两类职责：

- 语义检索：只需要知道用户到底在问什么。
- 结构化查询：需要用户 ID、当前时间等业务上下文。

之前把 SQL 需要的上下文硬塞给所有检索器，导致向量被噪声 token 拉偏，BM25 也会误命中“用户”“时间”等无关词。

## 解决思路

把两类输入拆开：

- 检索 Query 保持干净，只表达用户问题。
- 用户 ID、当前时间下沉到 SQL 检索器内部使用。

## 产品价值

这样既不牺牲 SQL 生成能力，又能保证知识库检索不被无关上下文污染。
