# MindBridge 设计与迭代记录

本文记录项目从“能对话”到“可评估、可审计、可部署”的演进路径。它不是功能清单，而是关键问题、设计取舍与验证方式的追踪文档。

## 原创设计主线

MindBridge 的核心不是简单套接大模型接口，而是围绕校园心理支持场景设计一条受约束的智能体链路：

1. **先路由，后检索**：普通闲聊不访问知识库，心理咨询和风险表达才进入 RAG，减少无关上下文与推理成本。
2. **风险守护独立于回复生成**：风险词典提供确定性兜底，模型负责语义判断；两条信号共同决定风险等级，避免把安全判断完全交给生成模型。
3. **评估结果与学生回复分离**：后台保留情绪、风险和置信度，学生端只获得自然、克制的支持性回复，降低标签化伤害。
4. **有限步多 Agent 协作**：记忆、路由、知识、风险和回复各自承担单一职责，并设置最大步数，兼顾可解释性与运行安全。
5. **高风险处置形成可审计闭环**：数据库记录、Excel 报告、通知工具按顺序执行，并保存每一步状态，便于复盘失败点。
6. **本地模型与数据隐私优先**：支持 Ollama + LoRA/GGUF 本地推理，同时保留 OpenAI 适配器，部署方可按隐私和效果要求选择。

## 迭代里程碑

### v0.1：可用的校园心理对话原型

目标：完成身份、会话、消息持久化和 SSE 流式对话。

- Spring Boot 3 + Spring Security 基础骨架
- 学生/管理员角色与演示账户
- 会话、消息、心理报告等领域模型
- `/api/chat/stream` 流式接口和单页 Web 客户端

验证：应用上下文测试、SSE 接口脚本化测试。

### v0.2：从单 Prompt 升级为受约束 Agent Loop

目标：让决策过程可拆分、可追踪，避免单次 Prompt 同时承担全部职责。

- `MemoryAgent` 恢复对话上下文和用户画像
- `SupervisorAgent` 识别 `CHAT / CONSULT / RISK`
- `KnowledgeAgent` 改写查询并判断是否二次检索
- `RiskGuardianAgent` 进行模型评估与规则兜底
- `CompanionAgent / CounselorAgent` 分别生成闲聊和心理支持策略
- 每轮最多 8 步，并记录 agent trace

验证：Agent Loop harness 覆盖路由、步骤顺序和终止条件。

### v0.3：混合 RAG 与长期记忆

目标：提升知识命中率，同时让支持方式随用户稳定偏好演进。

- Markdown 知识文件切块与启动增量导入
- BM25、本地轻量检索与 Chroma 向量检索可切换
- 结果重排、来源追踪、二次检索
- Redis 短期记忆 + MySQL 可审计记录 + Chroma 画像召回
- 9 个校园心理主题知识文档与 100 条 RAG 评测集

验证：检索单测、数据集完整性测试、RAGAS 可选评测流程。

### v0.4：安全处置与工具闭环

目标：让“识别到高风险”之后的动作可靠、可观测。

- 高风险报告持久化
- Excel 写入支持本地、HTTP 和 MCP 三种模式
- 通知支持日志、SMTP、HTTP 和 MCP 四种模式
- 严格执行“报告 → Excel → 通知 → 状态更新”
- 隐私清洗器避免工具链传播多余敏感信息

验证：风险 harness 覆盖分级、工具调用次序与失败状态。

### v0.5：本地模型与工程化交付

目标：形成可复现的开发、评测和部署链路。

- Qwen2.5-7B LoRA 微调、合并、GGUF 转换说明
- Ollama Modelfile 与模型创建脚本
- H2 轻量演示模式和 MySQL/Redis/Chroma 完整模式
- Docker Compose、运行脚本、发布打包脚本
- 面向复现的 RAG 技术指南和评测工具

验证：Maven 测试、Docker 健康检查、RAGAS 报告。

## 关键取舍

| 问题 | 选择 | 原因 |
| --- | --- | --- |
| 所有消息都做 RAG？ | 动态路由 | 闲聊不需要检索，减少噪声与时延 |
| 全靠模型判断风险？ | 模型 + 规则兜底 | 高风险场景需要确定性防线 |
| 把评估直接展示给学生？ | 前后台分离 | 避免诊断暗示和标签化 |
| 无限自主 Agent？ | 有限步状态机 | 更容易测试、审计和终止 |
| 只支持云模型？ | 本地优先、云端可切换 | 兼顾隐私、成本与模型效果 |
| 工具失败后继续通知？ | 顺序状态机 | 避免报告未落盘却发出不完整告警 |
